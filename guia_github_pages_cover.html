Objetivo
Propósito deste guia
Capítulo 1/16

Este guia reúne todas as informações necessárias para configurar, publicar e manter um site no GitHub Pages — desde a ativação inicial até a configuração de domínio personalizado e diagnóstico de erros.

🎯 Público-alvoDesenvolvedores, designers e qualquer pessoa que deseje hospedar sites estáticos gratuitamente com GitHub Pages.

O que você vai aprender:

  • Configurar o GitHub Pages do zero
  • Publicar um site HTML estático
  • Configurar domínio personalizado
  • Configurar DNS (CNAME e Registros A)
  • Resolver erros de publicação (404, SSL, etc.)
  • Diagnosticar problemas de acesso
  • Atualizar o site corretamente

Todo o conteúdo é baseado na experiência prática com o projeto InfoCelll e seu site hospedado em infocelll.github.io/infocelll.

03
Ativar o GitHub Pages
Primeiros passos para publicar
Capítulo 3/16

Siga os passos abaixo para ativar o GitHub Pages no seu repositório:

1. Acesse o repositório no GitHub
2. Clique em Settings
3. Clique em Pages no menu lateral
4. Em Source, selecione Deploy from a branch
5. Em Branch, selecione main
6. Em Folder, selecione / (root)
7. Clique em Save
8. Aguarde 1 a 5 minutos para o deploy
9. O GitHub fará o deploy automaticamente
✅ Resultado esperadoApós o deploy, o GitHub exibirá a mensagem: "Your site is live at https://infocelll.github.io/infocelll/"
⏱️ Tempo de propagaçãoO primeiro deploy pode levar até 5 minutos. Atualize a página de Settings > Pages para ver o status.

05
Domínio Personalizado
Configurar custom domain + HTTPS
Capítulo 5/16

Para usar seu próprio domínio (ex: www.infocelll.com.br):

1. Acesse: Settings → Pages
2. No campo Custom domain, informe:
  www.infocelll.com.br
3. Clique em Save
4. Habilite a opção Enforce HTTPS
5. O GitHub emitirá o certificado SSL automaticamente
🔒 HTTPS AutomáticoO GitHub emite certificados SSL/TLS via Let's Encrypt. A emissão pode levar de 1 a 30 minutos. O site continuará funcionando via HTTP enquanto o certificado não é emitido.
⚠️ ImportanteNão desabilite o Enforce HTTPS após ativá-lo. Isso pode expor seu site a riscos de segurança.

07
Verificar DNS
Confirmar propagação e configuração
Capítulo 7/16

Após configurar os registros DNS, confirme os seguintes pontos:

✅ Check DNS ✓ O registro CNAME www aponta para infocelll.github.io
✓ O domínio principal aponta para os 4 IPs do GitHub
✓ A propagação DNS foi concluída (use dig www.infocelll.com.br)
✓ O GitHub reconhece o domínio em Settings → Pages

Ferramentas úteis:

  • whatsmydns.net — Verificar propagação global
  • dnschecker.org — Checar registros DNS em múltiplas localidades
  • Terminal: nslookup www.infocelll.com.br
  • Terminal: dig www.infocelll.com.br CNAME
⏳ AtençãoA propagação DNS pode levar até 48 horas. Se o site não funcionar imediatamente, aguarde e verifique novamente.

Estrutura do Projeto
Organização de arquivos recomendada
Capítulo 8/16

Mantenha seu repositório organizado com a seguinte estrutura:

/ (raiz)
├── index.html ← Página principal (OBRIGATÓRIO)
├── robots.txt ← Instruções para motores de busca
├── sitemap.xml ← Mapa do site para SEO
├── manifest.json ← Manifesto para PWA
├── favicon.ico ← Ícone do site
├── css/ ← Folhas de estilo
├── js/ ← Scripts JavaScript
├── img/ ← Imagens e ícones
├── icons/ ← Ícones para PWA
├── assets/ ← Arquivos estáticos
└── fonts/ ← Fontes customizadas
📂 OrganizaçãoManter arquivos em pastas separadas (css/, js/, img/) facilita a manutenção e o versionamento.

09
Publicação dos Arquivos
4 métodos para enviar seus arquivos
Capítulo 9/16

Escolha o método mais adequado para publicar seus arquivos:

📁 Opção 1 — Upload de múltiplos arquivos (recomendado)

1. No repositório, clique em Add file → Upload files
2. Arraste ou selecione os arquivos:
  index.html, css/, js/, img/, etc.
3. Marque Commit directly to main
4. Clique em Commit changes

✏️ Opção 2 — Editar arquivo individual

1. Abra o arquivo (ex: index.html)
2. Clique no ícone ✏️ Edit
3. Faça as alterações
4. Role até o final e clique em Commit changes

🔄 Opção 3 — Substituir vários arquivos

1. Clique em Add file → Upload files
2. Envie novamente os arquivos com as alterações
3. Eles substituirão automaticamente os existentes
4. Commit changes

🚀 Opção 4 — Novo repositório (infocelll.github.io)

1. Crie novo repositório com nome: infocelll.github.io
2. Marque como Public
3. Clique em Create Repository
4. Faça upload dos arquivos
5. Configure Pages normalmente
💡 DicaA Opção 4 (repositório nomeado como {usuário}.github.io) faz o site ficar disponível na raiz https://infocelll.github.io/ sem o nome do repositório na URL.

10
Como Saber se Publicou
Verificar se o deploy foi concluído
Capítulo 10/16

Após o commit, verifique se o site foi publicado com sucesso:

1. Acesse: Settings → Pages
2. Procure pela mensagem:
  "Your site is live at https://..."
3. Se aparecer verde, o deploy foi concluído ✅
4. Se aparecer amarelo, o deploy ainda está em andamento ⏳
5. Se aparecer vermelho, houve um erro ❌
🔗 Acesse diretamenteAbra https://infocelll.github.io/infocelll/ no navegador. Se o conteúdo aparecer, o deploy foi concluído.

11
GitHub Actions
Acompanhar o status do deploy
Capítulo 11/16

O GitHub Actions executa automaticamente o deploy do Pages após cada commit.

1. Acesse a aba Actions do repositório
2. Procure pelo workflow "Deploy Pages"
3. Verifique o status:
  🟢 Verde = Deploy concluído com sucesso ✅
  🟡 Amarelo = Deploy em andamento ⏳
  🔴 Vermelho = Erro no deploy — clique para analisar ❌
📋 Logs de erroSe o deploy falhar, clique no workflow vermelho e depois em "Build" para ver os logs detalhados do erro.
⚡ DicaWorkflows com duração maior que 5 minutos geralmente indicam algum problema. Verifique os logs para identificar a causa.

Erro 404
Causas e soluções para página não encontrada
Capítulo 12/16

Cenário comum:

✅ Funciona: https://www.infocelll.com.br/index.html
❌ Não funciona: https://www.infocelll.com.br/

Possíveis causas do erro 404:

🔴 Pages desativado
Verificar Settings → Pages
🟡 Deploy incompleto
Aguardar Actions finalizar
🟠 DNS propagando
Aguardar até 48 horas
🔵 HTTPS emitindo
Certificado SSL em emissão
⚪ CNAME incorreto
Verificar arquivo na raiz
⚫ index.html fora da raiz
Mover para a pasta raiz
🔴 Domínio incorreto
Revisar Custom Domain
🚨 Diagnóstico rápidoSe /index.html funciona mas a raiz não, o problema está em uma destas configurações: Pages, Custom Domain, CNAME, DNS, HTTPS ou deploy.

13
Arquivo CNAME
Configuração do domínio personalizado na raiz
Capítulo 13/16

O arquivo CNAME deve ser criado na raiz do repositório e conter apenas o domínio personalizado.

// Arquivo: CNAME (sem extensão) // Conteúdo (apenas esta linha): www.infocelll.com.br

Regras importantes:

  • O nome do arquivo deve ser CNAME (sem extensão)
  • O conteúdo deve ser exatamente igual ao domínio configurado em Settings → Pages → Custom Domain
  • O arquivo deve ficar na raiz do repositório
  • Sem espaços extras ou linhas em branco
⚠️ AtençãoSe o conteúdo do CNAME não corresponder ao domínio configurado no Settings, o GitHub Pages pode ignorar o domínio personalizado ou exibir erro 404.

Capítulo 15/16

Siga estas boas práticas para manter seu site GitHub Pages saudável:

📝 Nomenclatura
• Letras minúsculas
• Sem espaços
• Sem acentos
• Sem caracteres especiais

• index.html na raiz

• robots.txt atualizado
• sitemap.xml gerado

⚡ Performance

Observação Final
Resolução de problemas persistentes
Capítulo 16/16

Cenário típico:

✅ Funciona: https://www.infocelll.com.br/index.html
❌ Não funciona: https://www.infocelll.com.br/

Se /index.html funciona mas a raiz não, o problema normalmente está em uma destas configurações:

  • GitHub Pages — Verificar se está ativo e publicado
  • Custom Domain — Confirmar se o domínio foi salvo corretamente
  • Arquivo CNAME — Verificar se o conteúdo corresponde ao domínio
  • DNS — Confirmar propagação dos registros
  • Certificado HTTPS — Aguardar emissão do SSL
  • Deploy — Confirmar que o Actions concluiu sem erros
🔑 Antes de alterar qualquer configuração, confirme: ✓ O domínio no GitHub Pages corresponde ao conteúdo do CNAME
✓ O DNS está propagado (use whatsmydns.net)
✓ O deploy foi concluído com sucesso (Actions verde)
✓ O arquivo index.html está na raiz publicada

Na maioria dos casos, alinhar essas quatro configurações resolve o problema.
